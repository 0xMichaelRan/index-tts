# Master S3 / R2 Bucket Architecture Specification

> **Current Architecture Status**: Fully Implemented & In Production  
> **Effective Date**: September 2026  
> **Participating Repositories**: `oracle-backend` (FastAPI Orchestrator / API Server) and `indexTTS-worker` (Inference & Rendering Background Worker)

---

## 1. Executive Summary & Background

### The Legacy 3-Bucket Problem
Prior to September 2026, the documentary video pipeline shared three buckets:
- `klatu-misc`: General assets, avatars, UI uploads
- `klatu-video`: Video clips and rendered MP4 outputs
- `klatu-audio`: **All audio indiscriminately**

This created severe architectural coupling:
1. **Co-mingled Ownership**: Synthesized TTS speech (generated by `indexTTS-worker`), user voice recordings (recorded in frontend, stored by `oracle-backend`), and external ElevenLabs audio voiceovers (manually uploaded by users) were all placed in `klatu-audio`.
2. **Ambiguous Lifecycle & Purging**: Voice training audio (permanent reference models) lived beside ephemeral TTS job tests and project-specific voiceovers.
3. **No S3 Provider Flexibility**: It was impossible to route heavy TTS output or user-uploaded audio to separate cost-optimized providers (such as Filebase or Cloudflare R2) without impacting voice cloning prompts.

### The 5-Bucket Solution
The storage layer was refactored into a **5-bucket unified registry architecture**. Each bucket has a single distinct purpose, explicit write ownership, and isolated credentials:

```
┌────────────────────────────────────────────────────────────────────────┐
│                      5-BUCKET ARCHITECTURE MATRIX                      │
├─────────────┬──────────┬──────────────────────┬────────────────────────┤
│ Bucket Name │ Type     │ Primary Writer       │ Main Contents          │
├─────────────┼──────────┼──────────────────────┼────────────────────────┤
│ klatu-misc  │ misc     │ oracle-backend       │ Avatars, images, temp  │
│ klatu-video │ video    │ oracle + indexTTS    │ Clips, rendered MP4s   │
│ klatu-audio │ audio    │ oracle-backend       │ Voice cloning prompts  │
│ klatu-tts   │ tts      │ indexTTS-worker ONLY │ TTS audio + align JSON │
│ klatu-11lab │ 11lab    │ oracle (user upload) │ ElevenLabs exports     │
└─────────────┴──────────┴──────────────────────┴────────────────────────┘
```

## 2. Master Bucket Specifications

### 2.1 `klatu-misc` (`type = "misc"`)
* **Purpose**: General miscellaneous application assets, user profiles, image decomposition, and short-lived upload buffers.
* **Writer**: `oracle-backend`
* **Readers**: `oracle-backend`, Frontend client
* **Typical S3 Keys**:
  - User avatars: `users/{user_id}/avatar_{timestamp}.jpg`
  - Beat decomposition images: `projects/{project_id}/beats/beat_{index:02d}.jpg`
  - Temporary multipart buffers: `temp/{upload_id}/...`
* **Env Prefix**: `S3_MISC_*`

---

### 2.2 `klatu-video` (`type = "video"`)
* **Purpose**: Video materials, individual beat animation clips (4-second animations), and composite rendered documentary noir videos.
* **Writers**:
  - `oracle-backend`: Ingests video clips from Google Flow / Midjourney / browser uploads
  - `indexTTS-worker`: `vox_render_pipeline` renders and uploads final composited MP4s
* **Readers**: `oracle-backend`, `indexTTS-worker`, Frontend video player
* **Typical S3 Keys**:
  - Beat animation clips: `projects/{project_id}/clips/beat_{index:02d}.mp4`
  - Rendered final documentary: `projects/{project_id}/renders/final.mp4`
  - Multi-locale Flow outputs: `flow/{YYYYMMDD}/{job_id}/{locale}.mp4`
* **Env Prefix**: `S3_VIDEO_*`

---

### 2.3 `klatu-audio` (`type = "audio"`)
* **Purpose**: **User voice recordings and voice cloning prompts ONLY.** This is the source library for TTS reference voices.
* **CRITICAL RULE**: Synthesized TTS speech is **NEVER** stored here.
* **Writer**: `oracle-backend` (user microphone recording, anonymous voice contribution, admin sample upload)
* **Readers**: `oracle-backend` (playback, validation), `indexTTS-worker` (downloads reference prompt for voice cloning)
* **Typical S3 Keys**:
  - Authenticated user voice sample: `voice-samples/{voice_id}/sample.wav`
  - Anonymous recorded voice: `voice-recordings/anon/{anon_id}/{filename}.wav`
  - Admin voice clone prompts: `audio-prompts/{voice_name}.wav`
* **Env Prefix**: `S3_AUDIO_*`

---

### 2.4 `klatu-tts` (`type = "tts"`)
* **Purpose**: Synthesized TTS audio outputs and word-level forced alignment JSON sidecars generated by `indexTTS-worker`.
* **CRITICAL RULE**: `indexTTS-worker` is the **SOLE WRITER**. `oracle-backend` has read-only access.
* **Writer**: `indexTTS-worker`
* **Readers**: `oracle-backend` (generates presigned download URLs, links project assets), Remotion / Video Render Pipeline
* **Typical S3 Keys**:
  - Synthesized speech: `{job_type}/{YYYYMMDD}/{job_id}/{language}_r{ratio}_{env}[_voice{id}].mp3`
  - Forced alignment JSON sidecar: `{job_type}/{YYYYMMDD}/{job_id}/{language}_r{ratio}_{env}[_voice{id}].json`
* **Database Asset Type**: `indextts15_voiceover` (migrated from legacy `tts_voiceover`)
* **Env Prefix**: `S3_TTS_*`

---

### 2.5 `klatu-11lab` (`type = "11lab"`)
* **Purpose**: User-uploaded ElevenLabs audio voiceover tracks exported outside the platform and manually imported per project.
* **Capacity Constraint**: Each project supports **0 or 1** uploaded 11labs track.
* **Writer**: `oracle-backend` (via frontend asset upload route `/api/projects/{project_id}/assets/voiceover`)
* **Readers**: `oracle-backend` (presigned playback), Video Render pipeline
* **Typical S3 Keys**:
  - Project voiceover export: `projects/{project_id}/voiceover/elevenlabs_{timestamp}.mp3`
* **Database Asset Type**: `11lab_voiceover`
* **Database Field**: `ProjectAssets.uploaded_voiceover_path`
* **Env Prefix**: `S3_11LAB_*`

## 3. Configuration & Registry Mechanics

Bucket metadata and secrets are split cleanly:
1. **Structural Configuration** (`config/buckets.toml`): Bucket names, logical types, regions, and enablement flags. Kept in source control.
2. **Secrets & Endpoints** (`.env`): S3 access keys, secret keys, and endpoint URLs. Never committed.

### 3.1 `config/buckets.toml` Specification
Identical across both repositories (`oracle-backend` and `indexTTS-worker`):

```toml
# Oracle / IndexTTS S3 Bucket Registry Configuration

[[bucket]]
name = "misc"
type = "misc"
bucket_name = "klatu-misc"
region = "auto"
description = "General miscellaneous assets, uploads, and temporary files"
enabled = true

[[bucket]]
name = "video"
type = "video"
bucket_name = "klatu-video"
region = "auto"
description = "Video assets, generated video clips, and rendered video outputs"
enabled = true

[[bucket]]
name = "audio"
type = "audio"
bucket_name = "klatu-audio"
region = "auto"
description = "User voice recordings and audio prompts for TTS voice cloning"
enabled = true

[[bucket]]
name = "tts"
type = "tts"
bucket_name = "klatu-tts"
region = "auto"
description = "IndexTTS synthesized audio output and forced alignment JSON (written exclusively by indexTTS-worker)"
enabled = true

[[bucket]]
name = "11lab"
type = "11lab"
bucket_name = "klatu-11lab"
region = "auto"
description = "User-uploaded ElevenLabs audio exports (uploaded from frontend)"
enabled = true
```

### 3.2 Environment Variables Standard (`.env`)

Each bucket type maps to its corresponding `S3_<TYPE>_*` environment variables:

```bash
# --- S3 Storage: MISC bucket ---
S3_MISC_ENDPOINT_URL=https://<account_id>.r2.cloudflarestorage.com
S3_MISC_ACCESS_KEY_ID=<access_key>
S3_MISC_SECRET_ACCESS_KEY=<secret_key>

# --- S3 Storage: VIDEO bucket ---
S3_VIDEO_ENDPOINT_URL=https://<account_id>.r2.cloudflarestorage.com
S3_VIDEO_ACCESS_KEY_ID=<access_key>
S3_VIDEO_SECRET_ACCESS_KEY=<secret_key>

# --- S3 Storage: AUDIO bucket ---
S3_AUDIO_ENDPOINT_URL=https://<account_id>.r2.cloudflarestorage.com
S3_AUDIO_ACCESS_KEY_ID=<access_key>
S3_AUDIO_SECRET_ACCESS_KEY=<secret_key>

# --- S3 Storage: TTS bucket ---
S3_TTS_ENDPOINT_URL=https://s3.filebase.io
S3_TTS_ACCESS_KEY_ID=<access_key>
S3_TTS_SECRET_ACCESS_KEY=<secret_key>

# --- S3 Storage: 11LAB bucket ---
S3_11LAB_ENDPOINT_URL=https://s3.filebase.io
S3_11LAB_ACCESS_KEY_ID=<access_key>
S3_11LAB_SECRET_ACCESS_KEY=<secret_key>
```

#### Credential Resolution Order:
1. `S3_<TYPE>_ACCESS_KEY_ID` / `S3_<TYPE>_SECRET_ACCESS_KEY`
2. Shared fallback: `S3_ACCESS_KEY_ID` / `S3_SECRET_ACCESS_KEY` (if per-type creds are omitted)
3. If any mandatory parameter (`endpoint_url`, `access_key_id`, `secret_access_key`, or `bucket_name`) is absent, that specific bucket is disabled with a warning log rather than crashing the system.

## 4. Code Integration & API Usage

### 4.1 `oracle-backend` Client Usage

```python
from app.s3.registry import get_bucket, get_bucket_by_type

# 1. Retrieve bucket configuration
misc_bucket = get_bucket("misc")          # By logical type or bucket_name
tts_bucket = get_bucket_by_type("tts")     # Resolves klatu-tts
lab_bucket = get_bucket_by_type("11lab")   # Resolves klatu-11lab
audio_bucket = get_bucket_by_type("audio") # Resolves klatu-audio

# 2. Generating presigned URL for TTS results (read-only from klatu-tts)
from app.tts.service import generate_tts_audio_url
url = await generate_tts_audio_url(audio_s3_path="studio/20260902/job123/en_r10_prod.mp3")

# 3. Uploading user ElevenLabs track (writes to klatu-11lab)
# app/project/router/assets.py handles this via ELEVENLABS_BUCKET_TYPE = "11lab"
```

### 4.2 `indexTTS-worker` Client Usage

```python
from services.s3_config import S3Client
from services.storage_manager import StorageManager

storage = StorageManager()

# 1. Download voice reference sample (reads from audio bucket: klatu-audio)
local_prompt = storage.download_audio_prompt(
    job_id=job_id,
    audio_prompt_path="audio-prompts/voice_01.wav"
)

# 2. Upload synthesized audio (writes to tts bucket: klatu-tts)
s3_audio_path = storage.upload_audio(
    job_id=job_id,
    local_path="/tmp/output.mp3",
    remote_path=f"studio/{date}/{job_id}/en_r10_prod.mp3"
)

# 3. Upload alignment JSON sidecar (writes to tts bucket: klatu-tts)
s3_alignment_path = storage.upload_alignment_json(
    job_id=job_id,
    local_parsed_json="/tmp/alignment.json",
    output_s3_path=s3_audio_path
)
```

## 5. Database Schema & Migration History

### Asset Types in `content.assets` table
* `indextts15_voiceover`: TTS audio synthesized by IndexTTS (stored in `klatu-tts`). Supports **0 to many** per project.
* `11lab_voiceover`: Manually uploaded ElevenLabs audio (stored in `klatu-11lab`). Supports **0 or 1** per project.
* Migration: `20260919_5bucket_refactor` automatically updated all historical `tts_voiceover` records to `indextts15_voiceover`.

### Project Voiceover Coexistence
A project may simultaneously reference both:
1. One active TTS voiceover (`indextts15_voiceover`)
2. One uploaded voiceover (`11lab_voiceover`)

The user selects which track is active using `project.voiceover_source` (`"tts"` vs `"upload"`).
